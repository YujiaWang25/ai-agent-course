#### Git协作基础：AI时代的版本管理

40分钟 · 新增 项目B

##### Part 1：开场导入（5分钟）

讲师开场：

你的工具已经从"单文件处理"升级到"批量处理"。但每次让AI修改代码后，旧的代码就被覆盖了——万一改坏了怎么办？今天我们要学：**用Git管理代码版本，让每次修改都"可追溯、可回退"** 。在AI协作开发中，Git是你最重要的"安全网"。

##### Part 2：Git核心概念（8分钟）

讲师讲解：

Git就像一个"游戏存档系统"——你可以随时保存进度，也可以随时回到之前的存档点。

概念| 类比| 命令  
---|---|---  
初始化仓库| 创建一个"存档文件夹"| `git init`  
添加文件| 选择哪些文件要存档| `git add .`  
提交（commit）| 保存一个进度点，附上备注| `git commit -m "描述"`  
查看历史| 查看所有存档记录| `git log`  
查看差异| 对比两次存档之间的变化| `git diff`  
回退| 回到之前的存档点| `git checkout`  
  
**AI协作中的Git最佳实践：** 每次让AI修改代码前，先commit一次。这样如果AI改坏了，你随时可以回退。

##### Part 4：AI协作中的Git工作流（7分钟）

讲师讲解：

推荐AI协作开发的标准Git流程：

  1. **修改前commit：** 保存当前稳定版本
  2. **让AI修改代码：** 生成新版本
  3. **测试验证：** 确保新版本工作正常
  4. **修改后commit：** 保存新版本，写明"AI修改了什么"



这个流程的核心是：**每次AI修改 = 一个独立commit = 可追溯、可回退** 。

📖 Git的概念和作用

**什么是Git？**

  * Git是一个分布式版本控制系统
  * Git的核心是"版本管理"：记录每次修改，随时可以回退
  * Git的优势是"可追溯、可回退、可协作"



**Git的作用：**

  * **版本管理：** 记录每次修改，随时可以回退
  * **协作开发：** 多人协作时，避免代码冲突
  * **代码备份：** 本地和远程都有备份，避免代码丢失



**关键认知：** Git = AI协作开发的"安全网"。不需要记住所有命令，只需要记住：每次改代码前，先commit。 

📖 Git的基本操作

**操作四步法：**

  * **步骤1：初始化Git仓库** — git init
  * **步骤2：添加文件到暂存区** — git add .
  * **步骤3：提交到本地仓库** — git commit -m "提交信息"
  * **步骤4：查看提交历史** — git log



**常用命令：**

命令| 作用| 示例  
---|---|---  
git init| 初始化Git仓库| git init  
git add .| 添加所有文件到暂存区| git add .  
git commit -m "信息"| 提交到本地仓库| git commit -m "初始版本"  
git log| 查看提交历史| git log  
git diff| 查看代码变化| git diff  
git status| 查看当前状态| git status  
  
**重要认知：** Git的基本操作不是"可有可无"，而是"必须掌握"。Git是AI协作开发的基础。 

📖 AI协作中的Git工作流

**工作流四步法：**

  * **步骤1：修改前commit** — 保存当前稳定版本
  * **步骤2：让AI修改代码** — 生成新版本
  * **步骤3：测试验证** — 确保新版本工作正常
  * **步骤4：修改后commit** — 保存新版本，写明"AI修改了什么"



**Commit message规范：**

  * **格式：** "类型：描述"
  * **类型：** feat（新功能）、fix（修复bug）、refactor（重构）、docs（文档）
  * **示例：** "feat: 添加批量处理功能"、"fix: 修复标题序号错误"



**关键认知：** 每次AI修改 = 一个独立commit = 可追溯、可回退。Commit message要写清楚"这次改了什么"。
