讲师指令：

📖 多文件验证的概念

**什么是多文件验证？**

  * 多文件验证是指用多个不同格式的文件测试工具，确保工具的通用性
  * 单文件通过 ≠ 工具通用
  * 核心：验证工具在不同输入下的表现



**为什么需要多文件验证？**

  * 每个文件可能有不同的格式和结构
  * 新文件可能暴露新的问题
  * 确保工具不是"专用"的，而是"通用"的



**关键认知：** 多文件验证 = 确保通用性。单文件通过不等于工具通用，必须用多个不同格式的文件测试。 

📖 批量测试方法

**测试用例设计：**

  1. **正常用例：** 标准格式的文件
  2. **边界用例：** 特殊格式的文件（超长标题、嵌套列表等）
  3. **异常用例：** 不符合格式的文件（缺失标签、乱码等）



**测试步骤：**

  1. **准备测试文件：** 准备3个以上不同格式的文件
  2. **逐一测试：** 用工具转换每个文件
  3. **检查结果：** 标题、加粗、表格、列表、引号是否正确
  4. **记录问题：** 对每个发现的问题进行记录



**重要认知：** 测试用例设计不是"随便找几个文件"，而是"系统设计"。正常用例、边界用例、异常用例都要覆盖。 

📖 回归测试流程

**什么是回归测试？**

  * 回归测试是指修改代码后，重新测试之前已通过的用例
  * 目的：确保新修复没有引入新问题
  * 核心：每次修改后，跑一遍所有测试用例



**回归测试流程：**

  1. **修改代码：** 修复发现的问题
  2. **回归测试：** 重新测试所有旧文件
  3. **验证结果：** 确保旧文件仍然通过
  4. **迭代优化：** 如果有新问题，继续修复



**关键认知：** 回归测试是AI协作开发的铁律。每次修改后，跑一遍所有测试用例，确保不引入新bug。

案例2：批量测试脚本

**任务：** 编写批量测试脚本

批量测试脚本示例： #!/usr/bin/env python3 import os import subprocess def batch_test(input_dir, output_dir): test_files = os.listdir(input_dir) for filename in test_files: if filename.endswith('.md'): input_path = os.path.join(input_dir, filename) output_path = os.path.join(output_dir, filename.replace('.md', '.docx')) print(f'正在转换：{filename}') result = subprocess.run(['python', 'md2word.py', '--input', input_path, '--output', output_path], capture_output=True, text=True) if result.returncode == 0: print(f'✓ {filename} 转换成功') else: print(f'✗ {filename} 转换失败') print(f'错误信息：{result.stderr}') if __name__ == '__main__': batch_test('./test_files', './output') print('\n批量测试完成！')

**适用场景：** 自动化批量测试

回归测试检查清单： 每次修改代码后，必须验证以下项目： [ ] 文件1：标准格式.md \- [ ] 标题是否正确？ \- [ ] 加粗是否生效？ \- [ ] 表格是否正常？ \- [ ] 列表是否正确？ \- [ ] 引号是否替换？ [ ] 文件2：特殊格式.md \- [ ] 超长标题是否正确？ \- [ ] 嵌套列表是否正确？ \- [ ] 复杂表格是否正常？ [ ] 文件3：异常格式.md \- [ ] 是否能处理异常？ \- [ ] 是否给出友好提示？ [ ] 新修复的问题是否解决？ [ ] 是否引入新的问题？ 测试人：_________ 测试日期：_________

**适用场景：** 回归测试管理
