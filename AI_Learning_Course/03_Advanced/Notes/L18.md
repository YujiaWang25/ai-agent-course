# 标题识别 r'^#\s*[\u4e00-\u9fa5A-Za-z0-9]' # 一级标题：以#开头后跟中文/英文/数字 r'^#{2}\s*[\u4e00-\u9fa5（]' # 二级标题：以##开头 r'^#{3}[\u4e00-\u9fa5\d]' # 三级标题：以###开头 r'^#{4,}[\u4e00-\u9fa5（]' # 四级及以上：以####或更多#开头 # 加粗语法 r'\\*\\*(.+?)\\*\\*' # 匹配**加粗内容** # 斜体（排除加粗） r'(?<!\\*)\\*(?!\\*)(.+?)(?<!\\*)\\*(?!\\*)' # 匹配*斜体*但不匹配**加粗**

讲师解读：

关键理解：**正则表达式就是一套"匹配规则"** ——告诉AI"你要找什么样的文字模式"。你不需要背这些符号，你只需要学会用AI来生成和解释它们。

📖 正则表达式的概念

**什么是正则表达式？**

  * 正则表达式是一种"文字搜索的超级加强版"
  * 正则表达式的核心是"模式匹配"——告诉AI"你要找什么样的文字模式"
  * 正则表达式的优势是"精确匹配、灵活搜索、批量处理"



**为什么需要正则表达式？**

  * 在Markdown转Word项目中，AI经常需要"识别标题"——这是一级标题还是二级标题？
  * 正则表达式可以精确匹配文字模式，提高处理效率
  * 正则表达式可以批量处理文本，减少人工操作



**关键认知：** 正则表达式 = AI生成 + 你验证 + 补充边缘情况。你不需要成为正则专家，但你需要会"读"正则——理解它匹配什么、漏掉了什么。 

📖 正则表达式的基本语法

**常用符号：**

符号| 作用| 示例  
---|---|---  
^| 匹配行首| ^# 匹配以#开头的行  
$| 匹配行尾| $# 匹配以#结尾的行  
*| 匹配0次或多次| a* 匹配0个或多个a  
+| 匹配1次或多次| a+ 匹配1个或多个a  
?| 匹配0次或1次| a? 匹配0个或1个a  
.| 匹配任意字符| . 匹配任意字符  
[]| 匹配字符集| [abc] 匹配a、b、c  
()| 分组| (ab) 匹配ab  
  
**常用模式：**

模式| 作用| 示例  
---|---|---  
\d| 匹配数字| \d 匹配0-9  
\w| 匹配字母、数字、下划线| \w 匹配a-z、A-Z、0-9、_  
\s| 匹配空白字符| \s 匹配空格、制表符、换行符  
  
**重要认知：** 正则表达式的基本语法不是"可有可无"，而是"必须掌握"。只有掌握了基本语法，才能理解正则表达式的含义。

#### 工作流编排：Agent的"流水线设计"

40分钟 · 融合新增 AI认知项目B

##### Part 1：开场导入（5分钟）

讲师开场：

上节课我们学了工具调用——AI能自己判断该用什么工具。但真实场景中，**一个任务往往不是"调一个工具"就完了，而是需要"调多个工具、有分支判断、有错误重试"的复杂流程** 。

这就是**工作流编排（Workflow Orchestration）** ——把多个AI能力像"流水线"一样串起来，让数据在各个环节自动流转。今天我们就来学这个。

##### Part 2：核心概念讲解（8分钟）

讲师讲解：

工作流编排有**四种核心模式** ：

  1. **顺序执行** ：A→B→C→D，一步一步来。比如：读文件→提取数据→整理格式→输出报告
  2. **条件分支** ：如果X→走A路线，如果Y→走B路线。比如：客户投诉→判断风险等级→低风险自动回复/高风险升级人工
  3. **并行执行** ：A和B同时进行，最后汇总。比如：同时查询三个数据源，然后合并结果
  4. **循环+重试** ：如果某步失败→重试N次→还是失败→走兜底。比如：API调用失败→等3秒重试→重试3次仍失败→使用缓存数据



**打个比方：** 工作流就像**快递分拣中心** ——包裹进来后，经过扫码（识别）、分拣（条件判断）、转运（工具调用）、异常处理（重试/退回），最终送到目的地。工作流编排就是设计这个"分拣流程"。

##### Part 3：案例剖析 — 项目B中的"隐藏工作流"（10分钟）

讲师讲解：

回头看我们的Markdown转Word项目，其实它就是一个**工作流** ：

步骤| 操作| 模式  
---|---|---  
1| 读取MD文件| 顺序  
2| 检测文件编码→如果不是UTF-8→转换编码| 条件分支  
3| 保护加粗语法（占位符替换）| 顺序  
4| 删除多余空格| 顺序  
5| 还原加粗语法（占位符还原）| 顺序  
6| 处理标题、列表、表格、引号| 并行（可同时处理）  
7| 生成Word文档| 顺序  
8| 如果生成失败→重试→仍失败→输出错误日志| 循环+重试  
  
**关键发现：** 第31轮那个"空格删了导致`**`被拆散"的bug，本质上就是**工作流顺序设计错误** ——"删除空格"应该放在"保护加粗"之后，而不是之前！

##### 🧠 认知加油站：Loop Engineering — 从"一次写完"到"循环纠偏"（5分钟）

讲师讲解：

我们刚才学的是"宏观工作流"——设计好步骤让Agent按顺序执行。但2026年6月，行业里提出了一个更前沿的概念：**Loop Engineering（循环工程）** 。

**Prompt Engineering vs Loop Engineering：**

  * **Prompt Engineering** 关心的是"怎么让AI第一次就输出好结果"——优化单次对话的质量
  * **Loop Engineering** 关心的是"怎么让AI在一轮轮反馈中持续纠偏直到任务完成"——设计一个"观察→调整→再行动"的循环系统



**打个比方：** Prompt Engineering是"写好一份菜谱让厨师照着做"，Loop Engineering是"让厨师每做一步就尝一口，咸了加水、淡了加盐，直到味道对了"。

**一个完整的Loop有五个阶段：** ① 意图设定（明确可验证的目标）→ ② 上下文采集（从代码库/日志中收集信息）→ ③ 行动（修改代码或运行命令）→ ④ 观察（捕获测试结果、编译错误）→ ⑤ 调整（根据观察更新计划并继续）。

**最核心的认知转变：** 测试失败不是错误，是**新的上下文** 。类型错误不是阻塞，是**关于某个假设被推翻的信号** 。一次失败的代码审查，是**驱动下一轮行动的观察** 。

**回到我们的项目B：** 第31轮"空格删了导致`**`被拆散"的bug，本质上就是一次Loop——我们观察到输出不对 → 分析原因 → 调整处理顺序 → 重新验证 → 确认修复。这就是Loop Engineering的实战应用。

**一句话记住：** Loop Engineering = 把"AI犯错"从Bug变成流程的一部分。AI不是一次写对，而是在循环中越改越好。
