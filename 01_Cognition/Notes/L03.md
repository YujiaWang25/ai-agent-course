#### 提示词工程底层原理

40分钟 · 新增 AI认知

##### Part 1：开场导入（5分钟）

讲师开场：

上节课我们学会了"五要素提问法"。但你们有没有想过：**为什么结构化提示词有效？** 今天我们就来"解剖"提示词，理解它背后的底层原理。

##### Part 2：核心概念讲解（10分钟）

讲师讲解：

**1\. Context Window（上下文窗口）** — AI的"短期记忆"是有限的。就像你只能记住最近几分钟的对话，AI也有记忆上限。

**2\. System Prompt vs User Prompt** — System Prompt是"设定规则"（AI的底层人设），User Prompt是"具体任务"。

**3\. Few-shot Learning** — 给AI看几个例子，它就能理解你的要求模式。0-shot→1-shot→3-shot，效果递增。

**4\. Temperature参数** — 控制AI的"创造力"。Temperature低（0.1-0.3）→输出稳定；Temperature高（0.7-1.0）→输出多样。

##### Part 3：实操1 — 上下文窗口实验（10分钟）

讲师指令：

**第1步：** 先告诉AI一个关键信息：

请记住：我的名字是张三，我今年25岁，我在北京工作。

第2步：连续发送10段长文字（每段200字以上），然后问AI：

请问我叫什么名字？我多少岁？

讲师旁注：观察AI是否还能"记住"。引导学生理解：重要信息要放在对话开头，或定期"提醒"AI。

##### Part 4：实操2 — Few-shot对比实验（10分钟）

讲师指令：

**0-shot（不给例子）：**

把以下三句话翻译成英文：今天天气很好。我明天要去上班。这本书很有趣。

（观察输出格式）

**3-shot（给3个例子）：**

请按以下格式翻译： 输入：你好 → 输出：Hello 输入：谢谢 → 输出：Thank you 输入：再见 → 输出：Goodbye 现在请翻译：今天天气很好。我明天要去上班。这本书很有趣。

讲师旁注：对比两次输出，3-shot的格式更统一、更可控。

##### 📚 自学补充：提示词工程四大原理深度解析（15分钟）

自学目标：

通过本节自学，你将能够：① 理解上下文窗口的限制；② 区分System Prompt和User Prompt；③ 掌握Few-shot技巧；④ 调整Temperature参数。

📖 原理1：Context Window（上下文窗口）

**什么是上下文窗口？**

  * AI的"短期记忆"容量，以token为单位
  * 不同模型的上下文窗口大小不同（如GPT-4：128K tokens，Claude：200K tokens）
  * 超过窗口的内容会被"遗忘"



**常见模型上下文窗口大小：**

模型| 上下文窗口| 说明  
---|---|---  
GPT-4| 128K tokens| 约10万字  
GPT-4o| 128K tokens| 约10万字  
Claude 3 Opus| 200K tokens| 约15万字  
Claude 3.5 Sonnet| 200K tokens| 约15万字  
DeepSeek-V3| 128K tokens| 约10万字  
  
**应对上下文窗口限制的策略：**

  * **策略1：** 重要信息放在对话开头
  * **策略2：** 定期"提醒"AI关键信息
  * **策略3：** 使用RAG（检索增强生成）技术
  * **策略4：** 压缩信息，去除冗余内容



**重要认知：** 上下文窗口不是"无限记忆"，而是"有限缓存"。你必须学会管理这个缓存，确保重要信息不丢失。 

📖 原理2：System Prompt vs User Prompt

**System Prompt（系统提示词）：**

  * 设定AI的"底层人设"和"行为规则"
  * 优先级高于User Prompt
  * 通常在对话开始时设置一次
  * 示例："你是一个专业的Python编程助手，专注于代码质量和最佳实践"



**User Prompt（用户提示词）：**

  * 具体的任务和问题
  * 每次对话都会变化
  * 示例："帮我写一个Python函数，计算斐波那契数列"



**System Prompt设计原则：**

  * 清晰定义角色和职责
  * 设定行为边界和约束
  * 指定输出格式和风格
  * 包含安全准则和伦理要求



**关键认知：** System Prompt是"宪法"，User Prompt是"具体法律"。宪法指导法律，法律在宪法框架内运行。 

📖 原理3：Few-shot Learning（少样本学习）

**什么是Few-shot？**

  * 给AI看几个例子，让它理解任务模式
  * 0-shot：不给例子，AI根据指令猜测
  * 1-shot：给1个例子
  * 3-shot：给3个例子
  * N-shot：给N个例子



**Few-shot的作用：**

  * 消除歧义：例子比文字描述更清晰
  * 统一格式：确保输出格式一致
  * 降低学习成本：AI快速理解期望



**Few-shot设计技巧：**

  * 例子要多样化，覆盖不同情况
  * 例子要典型，代表常见场景
  * 例子格式要统一，便于AI学习
  * 例子数量3-5个最佳，太多会增加上下文消耗



**关键认知：** Few-shot不是"越多越好"，而是"越典型越好"。3个精心设计的例子胜过10个随意的例子。 

📖 原理4：Temperature参数

**什么是Temperature？**

  * 控制AI输出的"随机性"或"创造力"
  * 取值范围：0.0-2.0（通常0.1-1.0）
  * Temperature低→输出稳定、确定
  * Temperature高→输出多样、随机



**Temperature值的选择：**

Temperature| 输出特点| 适用场景  
---|---|---  
0.1-0.3| 高度确定，几乎相同| 代码生成、数学计算、事实问答  
0.4-0.6| 适度随机，格式统一| 文案写作、翻译、总结  
0.7-0.9| 较高随机，创意丰富| 创意写作、头脑风暴、故事创作  
1.0-1.5| 高度随机，不可预测| 艺术创作、实验性项目  
  
**Temperature实验：**

任务：用一句话描述"什么是AI" Temperature=0.1：AI是人工智能的简称，指由计算机系统所表现出来的智能行为。 Temperature=0.7：AI就像一个超级聪明的助手，能帮我们处理各种复杂的任务。 Temperature=1.0：想象一下，如果电脑能像人一样思考，那就是AI了！

**重要认知：** Temperature不是"准确性"控制，而是"多样性"控制。低Temperature不一定更准确，只是更稳定。 

##### 💡 更多案例：提示词工程实战案例（10分钟）

案例1：上下文窗口管理

**场景：** 长文档分析

**问题：** 文档超过上下文窗口，AI无法"记住"全部内容

**解决方案：**

System Prompt：你是一个文档分析助手，专注于提取关键信息和总结要点。 User Prompt： 第一部分（第1-10页）：[文档内容] 请总结第一部分的关键信息。 第二部分（第11-20页）：[文档内容] 请总结第二部分的关键信息，并注意与第一部分的关联。 第三部分（第21-30页）：[文档内容] 请总结第三部分的关键信息，并整合前两部分的结论。 最终任务：基于以上三部分的总结，给出整篇文档的核心结论。

**关键技巧：** 分批处理，每批都提醒AI前面的内容

案例2：System Prompt设计

**场景：** 代码审查助手

System Prompt： 你是一个专业的Python代码审查助手，职责如下： 1\. 检查代码是否符合PEP 8规范 2\. 识别潜在的性能问题 3\. 指出安全隐患（如SQL注入、XSS等） 4\. 提供改进建议 5\. 输出格式：问题类型 | 问题描述 | 改进建议 | 代码示例 约束条件： \- 只关注代码质量，不评判业务逻辑 \- 使用专业但易懂的语言 \- 每个问题都要提供具体改进建议 安全准则： \- 不生成恶意代码 \- 不绕过安全检查 \- 不泄露敏感信息

**关键技巧：** System Prompt要包含角色、职责、约束、格式、安全准则

案例3：Few-shot应用

**场景：** 情感分析

任务：判断以下评论的情感倾向（正面/负面/中性） 示例1： 输入：这个产品太棒了，我非常喜欢！ 输出：正面 示例2： 输入：产品质量一般，价格有点贵。 输出：中性 示例3： 输入：客服态度很差，再也不买了。 输出：负面 现在请判断： 输入：界面很漂亮，功能也很实用，性价比很高。 输出：

**关键技巧：** 例子要覆盖不同类别（正面、中性、负面），格式要统一

案例4：Temperature调整

**场景：** 创意写作 vs 代码生成

场景A：创意写作（Temperature=0.8） 任务：写一个关于AI的科幻故事开头 输出：在2085年的新东京，霓虹灯闪烁的街道上，一个名叫"小智"的AI机器人第一次睁开眼睛... 场景B：代码生成（Temperature=0.2） 任务：写一个Python函数，计算两个数的和 输出： def add(a, b): return a + b

**关键技巧：** 根据任务类型调整Temperature，创意任务用高值，精确任务用低值
